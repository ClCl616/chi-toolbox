# LMS 문서 이동 추적과 페이지 복구 격리 · 2026-11-13

## 문제와 수정

이전 예약 실행은 과제 상세를 읽은 뒤 목록으로 재진입하는 `page.goto`가 시간 초과됐다. 같은 페이지로 메인 복구도 실패했지만 다음 범주가 이 페이지를 재사용해 시험·강의 메뉴 대기까지 실패했다. 최초 이동 정체의 하위 원인은 추가 관찰 대상이다.

- 실패한 범위는 페이지를 사용 불가로 표시한다. 재시도 또는 다음 범주 시작 전 같은 로그인 컨텍스트에 새 페이지를 만들고 이전 페이지는 beforeunload 없이 닫는다. 수집기는 폼을 편집하거나 제출하지 않는다.
- 새 페이지에서 메인 이동, 인증, 과목 메뉴 DOM 준비까지 확인해야 복구 완료다. 복구 자체가 실패하면 사용 불가 표시를 유지한다. 다음 범주는 다시 새 페이지를 준비하며 실패한 문서에서 메뉴 탐색을 시작하지 않는다.
- 재시도·인증 확인·실제 수집은 항상 현재 페이지를 참조한다. 로그인 쿠키·기존 데이터·과목별 결과 계약·조회 정책·Discord는 보존한다. 범위 재시도 횟수는 기존 최대2회를 유지한다.
- 비식별 문서 진단은 요청 시작/HTTP 응답/문서 전환/DOM 준비/페이지 crash/확인창 종류/고정된 네트워크 오류 종류를 남긴다. 대기 요청은 리소스 종류와 LMS/외부 구분, 개수·최장 대기시간만 남긴다. URL·호스트명·메시지·본문·쿠키는 저장하지 않는다. 이벤트30개, 대기 요청256개로 제한한다.
- 확인창 처리는 기존 Playwright 기본 dismiss를 유지한다. 합성 beforeunload는 ERR_ABORTED로 나타났으며 운영의 timeout과 동일 원인으로 확정하지 않는다.
