# LMS 수집 탐색 공유와 시간 측정

## 보존하는 정책

- 공지·자료는 전체 목록을 확인하고 신규·제목 변경 항목만 상세 조회한다. 기존 `board-checks.json`과 SQLite 기준을 초기화하지 않는다. 재시도 중 성공한 상세는 같은 주기 메모리에서 재사용한다.
- 과제·시험의 상세 상태 확인과 목록 일관성 검사, 온라인 강의 목록 전용 수집을 유지한다. 강의 콘텐츠·제출·응시·첨부 다운로드는 실행하지 않는다.
- 수집은 순차 실행한다. 기존 30초 응답 제한, 10초 요소 대기, 일시 오류 1회 재시도·2초 backoff, 인증 오류 시 중단을 유지한다. 실패 범주는 이전 정보를 보존한다. 별도 Discord Notifier 소스를 수정하지 않는다.

## 구조와 변경

- `session.py`: 한 주기에 브라우저/컨텍스트/페이지 하나, 수강 목록 탐색 한 번. 실제 화면에서 확인한 과목별 메뉴 링크만 메모리에 공유한다. 다른 호스트·과목·모호한 링크는 거부하며 URL을 추측하지 않는다. 복구 시 메뉴 캐시를 비우고 메인으로 이동한다.
- `collection.py`: 과목별로 공지→자료→과제→시험→강의를 처리한다. 기존 결과 타입·과목/범주별 오류 격리·재시도 함수를 재사용한다. 정상 9과목 기준 과목 진입은 45회에서 9회다.
- `boards.py`: 공지·자료의 기존 조회 조건과 파서를 보존하며 전달받은 메뉴에서 시작한다. `activities.py`: 기존 과제·시험·강의 탐색을 공유 세션에 맞춰 옮겼고, 파서와 결과 계약은 Notifier 것을 사용한다.
- 고정 1초 추가 대기를 요청 시작 간 최소 1초 간격으로 대체한다. 응답 시간이 이미 1초 이상이면 추가로 쉬지 않는다. 목록 응답 이후 DOM 렌더링은 실제 링크가 나타날 때까지 기다린다. 최초 수강 목록 탐색의 기존 대기는 유지하며 주기당 한 번만 수행한다.
- `worker.py`: 성공한 과목/범주 결과를 즉시 DB에 커밋하고 그 뒤 공지·자료 확인 기록을 저장한다. 공개 snapshot은 여전히 주기 끝에 한 번 생성한다. 전체 이벤트 정렬은 실제 관측/DB 변경 순서이며 이제 과목별 처리 순서다. 중간 실패 시 앞서 커밋한 결과를 반영하고 나머지는 이전 상태로 남긴다.

## 측정과 검증

private `metrics.json` 및 작업 로그의 `LMS metrics:`에 전체 시간, setup/범주별 소요 시간, document/xhr/fetch 요청 수, 상세 진입 시도 수, 재시도·결과·실패 수와 과목 진입 수를 남긴다. 요청 수는 LMS 호스트만 집계하며 정적 리소스는 제외한다. 상세 횟수는 클릭 시도 기준이다. URL·제목·과목명·계정·쿠키는 기록하지 않는다. 범주 시간에는 첫 메뉴 진입·인증 진단·재시도 대기가 포함될 수 있다. 전체 시간에는 DB/파일 저장 등도 포함된다.

합성 Edge 화면·임시 DB로 기존 조회 정책, 45개 범주 처리, 브라우저/수강 목록 1회 생성, 최소 간격, 메뉴 복구, 오류 격리, 인증 중단, 과제·시험 파서 동등성과 상세 1회, 강의 콘텐츠 조회 0회, 부분 실패 후 snapshot 및 private 측정을 검증한다. 테스트는 실제 LMS 요청을 가로채며 개인정보를 사용하지 않는다.

실제 서버의 읽기 전용 메뉴 smoke에서 9과목·45개 메뉴 경로·과목 진입9회·상세0회를 확인했다. 개선 전 관찰된 정상 실행은 2026-11-12 12:14:41~12:20:34(약353초)였으며 상세한 구간 측정은 없었다. 개선 후 실제 단축률은 정상 예약 실행의 측정으로 판단한다. 운영 검증을 위해 전체 수집을 중복 강제 실행하지 않는다.

## Windows 전달·복구

웹 앱 배포는 필요 없다. `CHI-TOOLBOX-LMS` 실행 완료 후 기존 활성 상태를 기록하고 잠시 비활성화한다. 백업 후 `workers/lms/{worker,projector,boards,popups,session,activities,collection}.py` 일곱 파일을 전용 worker 폴더에 함께 전달한다. 서버 Python/Notifier source에서 오프라인 테스트, 파일 해시·import/schema 검사를 거쳐 기존 활성 상태를 복원한다. 설치 스크립트도 같은 일곱 파일을 복사한다.

복구 시 이전 worker 파일을 복원하고 이번에 추가한 세 모듈은 제거할 수 있다. private/public 데이터·세션·확인 기록은 되돌리거나 삭제하지 않는다. `metrics.json`은 이전 worker가 사용하지 않으므로 남겨도 된다. GitHub origin push는 별도 요청 없이 하지 않는다.
