# V2 화면 주소 통일 (2026-11-05)

이 문서가 v2 경로의 현재 계약이다. 이전 화면 설계·운영 기록에 있는 /toolbox, /dev 주소는 아래 호환 경로로 읽는다. v1과 v2는 같은 운영 서버·인증·데이터 연결을 사용한다. /v2는 별도 데이터 샌드박스가 아니다.

## 주소

| 화면 | 운영 URL |
| --- | --- |
| 대시보드 | https://chitoolbox.com/v2/dashboard |
| 로그인 | https://chitoolbox.com/v2/login |
| 회원가입 | https://chitoolbox.com/v2/signup |
| LMS 새 소식 | https://chitoolbox.com/v2/lms |
| LMS 남은 과제 | https://chitoolbox.com/v2/lms/assignments |
| 설정 | https://chitoolbox.com/v2/settings |

- /v2 → /v2/dashboard. /v2/는 프레임워크의 슬래시 정규화 후 같은 목적지로 이동한다.
- /toolbox → /v2/dashboard, /toolbox/lms → /v2/lms, /toolbox/lms/assignments → /v2/lms/assignments, /toolbox/settings → /v2/settings.
- /dev/dashboard → /v2/dashboard, /dev/login → /v2/login. 기존 로그인 returnTo와 오류 인자는 유지하고 복귀 경로는 검증한다.
- /와 /login은 v1 그대로다. API(/api/toolbox/lms 포함)와 /auth/callback은 버전 경로로 바꾸지 않는다. 운영 경로·서비스 이름·DB·수집 작업 변경은 없다.

## 화면과 인증 계약

- app/v2/(workspace)는 공통 ToolboxShell, (auth)는 공통 로그인/가입 레이아웃을 사용한다. route group 이름은 URL에 나타나지 않는다.
- 대시보드 과제 카드는 /v2/lms/assignments로, 소식 카드는 /v2/lms로 이동한다. LMS 탭은 링크다. 직접 접속·새로고침·뒤로/앞으로가기로 선택을 복원한다.
- /v2/login과 /v2/signup은 각각 독립 URL이다. 전환은 방문 기록에 남으며 이메일 입력을 유지하고 비밀번호·검증 메시지·표시 상태는 초기화한다.
- 기본 로그인/세션이 있는 가입 완료 목적지는 /v2/dashboard. returnTo는 알려진 v2 workspace 경로만 허용하며 query/hash는 유지한다. 외부 주소, 인증 화면 루프, v1 또는 알 수 없는 경로는 대시보드로 대체한다. 과거 toolbox/dev 대시보드 복귀 주소는 새 주소로 변환한다.
- 미로그인 LMS 화면의 로그인 링크는 현재 화면을 returnTo로 전달한다. v2에서 시작한 Google OAuth는 screen=v2와 검증된 next를 /auth/callback에 전달한다. 이전 screen=dev도 호환한다. 실패/취소는 /v2/login으로 돌아간다.
- v2 가입 요청은 screen과 returnTo를 전달하고 확인 메일의 callback에도 동일한 목적지를 넣는다. 세션이 없는 가입 응답은 기존 로그인 안내를 유지한다. 실제 메일 수신·계정 생성·OAuth 성공은 실계정 별도 확인 대상이며 자동 테스트는 운영 계정을 생성하지 않는다.
- 모든 v2 화면의 robots는 noindex/nofollow다. 이는 접근 제어가 아니며 LMS 데이터 접근은 기존 소유자 인증 정책으로 보호한다.

## 로컬 검증

Node 24와 npm ci로 의존성을 준비한다. 기존 설치 환경이면 재설치할 필요가 없다.

~~~powershell
npm.cmd run check
npm.cmd run build:test
npm.cmd run test:smoke
$env:TEST_BROWSER='msedge'
node scripts/run-browser-tests.mjs toolbox
node scripts/run-browser-tests.mjs lms
node scripts/run-browser-tests.mjs dev-login
git diff --check
~~~

build:test와 browser runner는 dummy 인증 환경 및 임시 LMS 데이터만 사용한다. 일반 로컬 실행은 운영 Supabase에 연결될 수 있다. UI 프리뷰는 npm.cmd run preview:toolbox 후 http://127.0.0.1:13003/v2/dashboard 를 연다. 테스트용 가입/로그인 성공은 모의 응답이다.

## 운영 전달과 확인

검증된 로컬 main 커밋을 Git bundle로 전달하고 서버의 C:/Services/chi-hub에서 fast-forward한 뒤 deploy/windows/deploy.ps1을 실행한다. 기존 배포 스크립트가 production build, 후보 health 검사, 활성 릴리스 교체 및 실패 시 복구를 담당한다. 환경 파일은 출력·커밋하지 않는다. origin push는 수행하지 않는다.

배포 후 /api/health, 위 여섯 화면 HTTP200, 호환 주소의 Location, 미인증 /api/toolbox/lms HTTP401, Google 시작 및 취소 복귀를 확인한다. LMS worker를 검증 목적으로 실행하지 않는다. 서버 최신 소스 bundle은 C:/Services/chi-toolbox-windows.bundle이다. rollback.ps1은 직전 앱 릴리스를 복원한다.
