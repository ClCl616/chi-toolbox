# 공통 UI와 빈 화면

## 범위와 확인 경로

새 MVP의 공통 UI는 `/toolbox`에서 확인한다. 기존 `/`, `?view=...`, 로그인·API·운영 데이터는 유지한다. 미완성 MVP로 기존 서비스를 교체하지 않기 위한 단계적 진입점이며, 별도 앱이나 복제 저장소가 아니다.

| 경로 | 화면 |
| --- | --- |
| `/toolbox` | 핵심 수치 카드와 카드 편집 |
| `/toolbox/lms` | 새 소식의 미연결 상태 |
| `/toolbox/lms/assignments` | 남은 과제의 미연결 상태 |
| `/toolbox/settings` | 현재 설정 범위 안내 |

PC는 왼쪽 내비게이션, 820px 이하는 하단 내비게이션이다. LMS는 새 소식 / 남은 과제 탭 경로로 나뉘며 직접 URL 접근·새로고침·뒤로 가기를 지원한다. 데이터가 없으므로 집계값 `0`이나 가짜 메시지를 표시하지 않고 `—`와 연결 필요 안내를 표시한다.

현재 경로는 개인 데이터를 전혀 읽지 않는 공개 UI다. 기존 로그인 화면과 인증 서버는 변경하지 않는다. 향후 실제 데이터 연결 전에 사용자 인증·소유권 경계를 적용해야 한다. UI를 열었다는 사실이 로그인·LMS 연결 성공을 의미하지 않는다.

## 파일 소유권

- `app/toolbox/`: 얇은 URL 진입점, 레이아웃, 로딩·오류 경계.
- `shell/toolbox/`: 공통 내비게이션·반응형·색상 토큰.
- `features/dashboard/`: 카드 구성, 표시·숨김, 순서, 브라우저 저장.
- `features/lms/`: LMS 화면과 연결 전 상태. 수집·API 구현은 아직 없음.
- `features/settings/components/toolbox-settings.tsx`: 현재 설정 범위 안내.
- `shared/components/toolbox-ui.*`: 공통 페이지 헤더, 버튼 스타일, 로딩·미연결·빈 상태·오류 표시.

CSS Module을 각 소유 파일 옆에 두고 새 전역 CSS나 기존 스타일 override를 추가하지 않는다. 기존 workspaces registry는 운영 화면용이며, 신규 `/toolbox` 화면을 그 registry에 중복 등록하지 않는다. 공통 요소는 두 기능에서 실제로 재사용할 때 추출한다.

## 카드 편집 계약

- 보기 상태에서는 카드 전체가 해당 LMS 탭으로 연결된다.
- 편집 상태에서는 두 카드 모두 표시해 숨긴 카드도 복구할 수 있다.
- 표시 스위치, 드래그 핸들, 키보드·터치용 앞으로/뒤로 버튼을 제공한다.
- 저장할 때만 브라우저 localStorage의 `chi-toolbox-dashboard-layout-v1`에 순서와 표시 여부를 기록한다.
- 취소 또는 저장 전 화면 이동은 초안을 버린다.
- 모두 숨겨도 카드 선택 버튼과 주 메뉴로 복구·이동할 수 있다.
- 잘못된 저장 데이터는 기본 구성으로 복구한다. 저장소 접근·저장 실패는 사용자에게 알리고 성공으로 표시하지 않는다.
- 이 저장값은 계정 설정이 아니다. 같은 브라우저 사용자는 같은 구성을 공유하며 계정·기기 간 동기화는 없다. 저장 내용에는 LMS·개인 데이터가 없다.

## 검증

```powershell
npm.cmd run check
npm.cmd run build:test
npm.cmd run test:smoke
$env:TEST_BROWSER='msedge'
npm.cmd run test:toolbox
npm.cmd run test:browser
```

`test:toolbox`는 dummy production 서버를 자동 시작·종료한다. API 요청을 차단하고 요청 건수가 0인지 확인한다. 화면 이동·히스토리·카드 편집·저장 실패·손상된 저장값·4개 경로×5개 너비를 검사한다. 캡처는 Git 제외 `work/qa/toolbox-*.png`에 저장한다. 기존 `test:browser`는 기존 서비스 회귀 검사다. 실제 DB 쓰기나 LMS 수집을 실행하지 않는다.
